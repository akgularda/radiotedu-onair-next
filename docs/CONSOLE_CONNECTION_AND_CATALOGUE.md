# Console startup and retained catalogue labels

The console previously discovered engine pipes on page load but required a separate System → Connect action before reading the current programme. The authorized local console now selects only the installed `onair-next-dev-service` endpoint automatically and reads its status. A delayed service appearance is retried; preview sessions, incomplete session responses and other development engines remain unselected. Explicit console disconnection is respected. Connection sends GET requests only and does not start, stop or skip broadcasts.

The real studio script is exercised with a lightweight DOM fixture. Five startup/session/disconnection cases plus the existing browser model checks pass: thirty cases in total. These are script/model tests, not a claim of direct visual browser acceptance. The installed HTTP endpoint was independently checked for the exact patched asset hash and its authenticated status response contained all eight running stations and sixteen connected outputs.

The broadcasting PC received this as a reversible static console asset patch, with a retained original file and patch receipt. Engine and web-host binaries remain source `6e40e91`; the UI patch source is `547b7421a211f90ad20b74de465b49648617898b`. The package manifest was retained rather than represented as a newly rebuilt package. No engine restart was performed.

A separate read-only comparison of the actual former application's settings and current library roots confirmed all eight music assignments match. Some media files lacked artist/title tags while the former catalogue held curated labels. Those catalogue labels had not accompanied the initial file-based migration. After a consistent database backup, 3,220 missing/fallback entries were restored through the existing version-checked metadata command, using exact same-station file-path matches. Existing edited assets and ambiguous matches were excluded. Readback verified every restored entry, unchanged base asset rows and unchanged music/branding roots. No media file tags or bytes were rewritten.

Metadata edits retain the existing immutable-playback semantics: historical attempts are preserved, and subsequent selections use the saved labels. Existing Lo-Fi broadcast metadata suppression remains in force. Private catalogue records, file paths, database snapshots and access tokens are not included here.
