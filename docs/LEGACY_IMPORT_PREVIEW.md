# Legacy import preparation

System > Legacy import reads a selected local data directory through the new authenticated engine. All new stations must be stopped and have zero configured outputs. Choose the directory containing cleanroom.db, prepare a preview, inspect saved folders and primary destinations, then explicitly save station-to-channel mappings. Reloading reads the retained plan and revision; retries preserve the original preview ID. Clearing a browser retry reminder does not cancel engine work.

The reader uses a read-only, short SQLite snapshot with a two-second busy timeout. It never modifies the former database, retrieves or exports source-password values, imports AI settings, scans music, launches audio, resolves credentials or changes stream ownership. It chooses an already verified legacy recovery receipt and independently checks that immutable file’s byte count and SHA-256 at a bounded 2 MiB/s on a dedicated worker. This verifies the encrypted artifact against the former program’s restore-verification receipt; it is not a new independent decryption/restore test. Linked paths, unknown mapping targets, duplicate primary destinations and /en or /fr assignments are rejected. The control response is bounded to 60,000 UTF-8 bytes.

Preview and mapping files are kept under the new protected data directory. Review the primary and secondary output destinations together. Secondary profiles and bitrates reflect the former program's fixed high/low contracts, and a duplicate enabled destination or externally owned mount cannot be mapped. The preview records only whether a credential is present. Prepare a fresh preview if an earlier version showed only primary outputs. A saved mapping does not arm a station. Branding files and cadence, service-readable music, protected credential transfer, output commissioning, source fencing and UI rollback remain required before any production takeover. No Apply or Start action is exposed by this preparation step. A process restart marks unfinished previews Interrupted instead of silently repeating a large recovery-file read.

Saved programme dates, recurrence, station scope, displayed title and cadence appear for review. The former program’s enabled flag is a saved setting; it does not mean a past window still applies or that Next will play the rule. In the November 2026 inventory, the two 29 October rules were one-time and already ended, the Energize test was disabled, and PowerApp was a distinct every-five-completed-songs rule on the main station. Keep that station’s existing programme owner until equivalent automatic playback is verified in Next.

Qualification of this new preparation workflow is pending. The current static browser is a disconnected visual preview; mouse testing that view does not qualify a connected service, real backup, real folders or live transfer.
