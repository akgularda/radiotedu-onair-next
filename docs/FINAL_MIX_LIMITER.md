## Detection and gain envelope

The four-times detector uses the ITU-R BS.1770-5 English Annex 2 twelve-tap polyphase kernel shared with the separately qualified meter. It also bounds original sample peaks. For a phase support, P=abs(sum(h*x)) and S=sum(abs(h*x)). The gain changes by at most 1 dB/ms on attack and 0.05 dB/ms on release. Over 11 sample intervals its maximum ratio is 1+epsilon=10^(11/(48*20)). Therefore a conservative processed phase bound is g_min*(P+epsilon*S). Every sample is constrained by all phase supports containing it. A bounded monotone-queue envelope anticipates the required attenuation while preserving those slopes. This inequality/envelope is our engineering method, not a processing algorithm prescribed by the standard.

A 60 ms fixed read-ahead covers the detector support and attack horizon; source/microphone samples outside +/-64 are explicitly rejected as malformed, so their valid mixed sum is bounded to +/-128. The horizon check rejects unsupported settings. A 0.001 dB numerical reserve covers float output rounding. Scratch/history/deque storage is fixed and processing performs no file, database or network I/O. Exact input/output frame counts are exposed. Finite drain advances only detector/lookahead zeros and emits only real input samples; it never appends programme silence. Unity-gain material retains its original float samples and 24bit precision.

## Prepared versus published ownership

The decoder may prepare future PCM, immutable source slices and boundary intents. Preparation does not append started/completed events, advance cadence or consume queue ownership. The audio clock and UI source/position follow processed output frames. Start at an output span's end stays unheard; terminal at that end belongs to the span. This preserves exact boundaries for sources shorter than the processing delay and multiple sources inside a 20 ms output block. Decoder EOF determines a transition, not an estimated display duration.

Auditable boundaries/checkpoints are submitted to the existing FULL-WAL writer without blocking the programme loop. Outstanding tickets are bounded and checked for failures. Queue IDs stay excluded until their terminal transaction is durably acknowledged; planners must exclude every in-flight ID. Shutdown drains with a bounded deadline while independently releasing owned outputs/decoders. A commit timeout/failure remains visible and cleanup can be retried. Publication and disk commit cannot be physically atomic: restart retains a last-committed-prefix uncertainty rather than inventing confirmed listener delivery. Timing remains programme sample-clock timing.

An operator Skip targets the observed audible occurrence. If its EOF is already buffered, finishing that tail cannot skip the unheard successor. A late accepted Skip against an already terminal occurrence is marked processed durably. Explicit Stop discards future preparation and checkpoints only the audible unfinished item; recovery restarts that item at its beginning with linked attempts. Completed committed items remain consumed. Network output recovery never resets the processor or programme.
