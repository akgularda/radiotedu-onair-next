# Audio tools review on the broadcasting PC

The exact-source `60efa680` Windows package passed hosted qualification. Its console was then opened in the built-in browser and connected to the separate, stopped development service using the System screen. The original broadcaster was left running.

The first real mouse-driven **Review additions** attempt did not produce a review. It remained at a generic Checking message, then reported a generic setup failure. No completion action was available or applied. The precise internal failing step was not observable, so a permission failure or slow verification must not be reported as a proven root cause.

The review now emits fixed, allowlisted progress steps over the owned helper's standard-error pipe. The console displays these steps without exposing file paths or raw exception data. The helper remains read-only and checks both installation ownership and the unarmed service before and after verification. All file hashes, provider lineage, and unchanged original codec checks remain required.

The helper has a ten-minute deadline; the console has an eleven-minute cleanup deadline. This gives large complete package verification more time on the busy target PC without launching additional work or increasing concurrency. Timeout and protected-file failures identify the last step. Failed or cancelled reviews install no files and cannot enable Apply.
