# Non-destructive source gain

Exact source `cf39fd9c` passed 179 unit cases, 8 browser-model cases, 148 real audio checks across eight scenarios, 35 SCM checks, 20 setup checks and nine independent synthetic instrument signals in [run 38842202973](https://github.com/akgularda/radiotedu-onair-next/actions/runs/38842202973). All six retained archive digests and execution source identities were verified. See [scoped evidence](../artifacts/evidence/source-normalization-179-20261016.json). This is not commissioning or all-stream compliance.

This development slice measures each newly validated source through one complete FFmpeg decode, in the same stereo float 48 kHz format as playback. It hashes the read-locked original and saves the completed ebur128 I/oversampled true-peak result with file size, modification time and a versioned analysis identity. Sub-minute LRA is withheld. Original media is never rewritten.

Playback applies one constant gain per source: the lower of the -23 LUFS target gain, a +12 dB boost bound and the measured source true-peak headroom to -1.4 dBTP. The 0.4 dB reserve is a provisional engineering choice for finite measurement/summary precision; it is **not measured codec headroom or a universal true-peak guarantee**. Peak/boost constrained sources are explicitly below target. Silence or material without a gated programme has no invented target loudness; a finite source peak can still cause attenuation. No time-varying loudness AGC or dynamic-range compressor is introduced.

A changed measured file revision is rejected before decoding. Measured files stay read-locked while their decoder is owned; this protects an open/prepared source on Windows. The source hash is established by import analysis, not recomputed on the programme clock. Fixed gain adds no lookahead, programme delay or sample padding. Attempt start/terminal records retain the actual source gain. Older engineering playlists without measurements continue as visibly Unmeasured: they do not establish the required broadcast workflow. Normal library validation measures old unmeasured catalog entries before eligibility.

The Library metadata editor displays source measurements, predicted post-gain loudness and the applied gain. Analyze loudness queues a durable request with persisted read-back, command deduplication and optimistic edit version checks. Reanalysis of an unchanged Ready source keeps its previous validated gain and eligibility available while the background lane runs. Rescanning never changes original files or manual tags. Restored/changed/invalid files cannot reuse stale analysis. Measurement payload hashes and revision checks fail closed on inconsistent stored evidence.

## Scope and remaining work

The final-mix meter remains after microphone ducking/mixing. Source peak headroom cannot constrain the sum of microphones, crossfades or overlay branding. **A genuine final-mix true-peak limiter, operating loudness controls, all 18 independently decoded outputs/codec-specific headroom and full commissioning remain unfinished.** No source prediction is labelled output compliance.

A disposable Windows CI scenario uses five generated signals (ordinary/loud/quiet/transient/silence), complete actual FFmpeg validation and actual decoder PCM, an independent native meter, finite engine publication/event boundaries, unchanged original hashes and owned-worker cleanup. It also independently decodes two real loopback AAC-LC/FLAC branches of the low-crest synthetic programme; these do not qualify worst-case codec headroom or the complete 18-output roster. The existing bit-precision fixture remains an explicitly unmeasured transport test. Source-gain tests and evidence must be assessed for their exact Git source; the earlier 171-unit/95-audio evidence predates this slice. No production media, listener recordings, legacy database or live service is used by these tests.

The loopback listener instrument must measure decoded samples rather than trim against a late Ogg granule timestamp. Its analysis-only clock is rebased with [FFmpeg asetpts](https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts), and an independent astats sample count must confirm exactly 192,000 stereo frames for the four-second window. Numeric readings and bounded diagnostics are retained before assertions, including failures. This changes the test instrument, never the transmitted programme timeline.
